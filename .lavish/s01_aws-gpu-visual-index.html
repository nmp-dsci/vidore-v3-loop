1 · what happens

One machine, rented for under an hour

The GPU only does the slow part: turning each page image into EVIE's ~1,019 small vectors. Search, the reranker and the viewer stay on the Mac and read the same files they read today.

2 · why it is so much faster

Seconds per page

EVIE is built on Qwen3.5, whose attention layers ship fast code for NVIDIA GPUs only. On the Mac it falls back to slow generic code, and the Mac's GPU is ~20× smaller than an L4 for this kind of maths to begin with.

Mac, swapping (measured)25.5 s
Mac, memory free (measured)9.6 s
L4, slow case (estimate)1.5 s
L4, expected (estimate)≈ 0.5 s

How the estimate is made. A page is ~1,019 image tokens through a 4.5B-parameter model, roughly 13 trillion operations. The Mac's GPU peaks around 5 TFLOPS and measured 9.6 s; the L4 peaks around 120 TFLOPS in bf16. Scaling the Mac's measured efficiency gives ≈ 0.4–0.5 s; the "slow case" allows for the fast kernels failing to install. Step 4 times 50 pages before the full run, so you see the real number after about a minute.

3 · which machine

Pick the smallest GPU with 24 GB and bf16

EVIE needs ~9 GB of GPU memory in bf16 plus working space for each pair of pages. Every option below fits; the L4 is the cheapest one that also runs bf16 natively. Prices are on-demand Linux per hour, from AWS's public price list today; EC2 bills by the second.

5 · the steps

From your terminal to a finished index

Run them in order. Mac lines run in this repo on your Mac; GPU lines run on the instance over SSH. Nothing costs money until step 2.

Log in to AWS and check the GPU quota New accounts often start with a GPU quota of 0, and raising it is a support request that can take hours to a day. This is the one thing to check first. The quota is in vCPUs; g6.xlarge needs 4.
Mac 
aws sso login --profile AdministratorAccess-089783391188
export AWS_PROFILE=AdministratorAccess-089783391188 AWS_REGION=ap-southeast-2

# "Running On-Demand G and VT instances", in vCPUs: need ≥ 4
aws service-quotas get-service-quota --service-code ec2 --quota-code L-DB2E81BA --query Quota.Value

# if it says 0, ask for 8 (then wait for the approval email)
aws service-quotas request-service-quota-increase --service-code ec2 --quota-code L-DB2E81BA --desired-value 8
Create a key, a firewall rule for your IP only, and launch The AMI is AWS's Deep Learning Base image (Ubuntu 22.04, NVIDIA driver and CUDA preinstalled). The instance is set to terminate itself when it shuts down, which is what makes the safety timer in step 3 work. Everything is tagged project=vidore-v3-loop.
Mac 
aws ec2 create-key-pair --key-name vidore-gpu --query KeyMaterial --output text > ~/.ssh/vidore-gpu.pem
chmod 600 ~/.ssh/vidore-gpu.pem

SG=$(aws ec2 create-security-group --group-name vidore-gpu-ssh \
      --description "SSH from one IP for the vidore GPU run" --query GroupId --output text)
aws ec2 authorize-security-group-ingress --group-id $SG --protocol tcp --port 22 \
      --cidr $(curl -s https://checkip.amazonaws.com)/32

AMI=$(aws ssm get-parameter --query Parameter.Value --output text \
      --name /aws/service/deeplearning/ami/x86_64/base-oss-nvidia-driver-gpu-ubuntu-22.04/latest/ami-id)

ID=$(aws ec2 run-instances --image-id $AMI --instance-type g6.xlarge \
      --key-name vidore-gpu --security-group-ids $SG \
      --instance-initiated-shutdown-behavior terminate \
      --block-device-mappings 'DeviceName=/dev/sda1,Ebs={VolumeSize=100,VolumeType=gp3,DeleteOnTermination=true}' \
      --tag-specifications 'ResourceType=instance,Tags=[{Key=project,Value=vidore-v3-loop},{Key=purpose,Value=visual-index}]' \
                           'ResourceType=volume,Tags=[{Key=project,Value=vidore-v3-loop},{Key=purpose,Value=visual-index}]' \
      --query 'Instances[0].InstanceId' --output text)
aws ec2 wait instance-running --instance-ids $ID
IP=$(aws ec2 describe-instances --instance-ids $ID \
      --query 'Reservations[0].Instances[0].PublicIpAddress' --output text)
echo "$ID  $IP"        # the billing clock is now running
If AWS says there's no g6 capacity, swap in g5.xlarge; nothing else changes.
Set up the GPU box, with a safety timer The timer shuts the machine down after 4 hours no matter what, and because of step 2 a shutdown means terminate: a forgotten instance can't bill you overnight. The two extra packages are EVIE's NVIDIA-only fast code; if they fail to build, carry on, as it still runs on the GPU, only slower (the "slow case").
GPU 
ssh -i ~/.ssh/vidore-gpu.pem ubuntu@$IP

sudo shutdown -h +240                       # safety timer: gone in 4 h whatever happens
nvidia-smi                                  # should show one NVIDIA L4

curl -LsSf https://astral.sh/uv/install.sh | sh && source ~/.local/bin/env
git clone -b project-init https://github.com/nmp-dsci/vidore-v3-loop && cd vidore-v3-loop
uv sync --extra retrieval                   # same locked versions as the Mac (uv.lock)
uv pip install --no-build-isolation flash-linear-attention causal-conv1d
source .venv/bin/activate
export HF_TOKEN=hf_...                      # optional: faster Hugging Face downloads; paste it here, never in a file
tmux new -s idx                             # so a dropped SSH connection doesn't stop the run
Fetch the pages, then time 50 of them --limit 50 encodes only the first batch of 50, then writes stats.json with the real seconds per page. Expect roughly 0.3–1.5. Anything above ~3 means the GPU isn't being used, so stop and tell me.
GPU 
vidoreloop pages --dataset finance_en         # 2,942 page images at the pinned revision
vidoreloop index --dataset finance_en --stage visual --model evie --limit 50
cat data/cache/index/finance_en/visual/evie/stats.json      # look at seconds_per_page and "device": "cuda"
Run the rest Same command without the limit. It skips the batch already done and carries on; if anything stops it, rerun the same line and it resumes at the last finished batch of 50. On Linux the Mac's memory guard switches itself off.
GPU 
vidoreloop index --dataset finance_en --stage visual --model evie
cat data/cache/index/finance_en/visual/evie/stats.json      # want "pages": 2942, "complete": true
I'd rebuild all 2,942 rather than upload the Mac's 750: it's ~6 more minutes (about 10 cents), one fewer step, and every page then comes from the same machine.
Copy the index home and check it The Mac's 750-page index is moved aside rather than deleted, as a fallback. The viewer keeps the index in memory, so it needs a restart to pick up the new one.
Mac 
V=data/cache/index/finance_en/visual
mv $V/evie $V/evie.mac-750                     # keep the old one until the new one checks out
rsync -av -e "ssh -i ~/.ssh/vidore-gpu.pem" \
      ubuntu@$IP:vidore-v3-loop/$V/evie/ $V/evie/
cat $V/evie/stats.json                          # "pages": 2942, "complete": true
# then restart the viewer: make viewer
In the RAG pipeline tab the status line turns from "(partial)" to complete. Try q181: its Morgan Stanley answer page could never appear in the visual column before.
Delete everything you created Terminating also deletes the disk. The last command should print nothing; if it lists anything, it is still billing.
Mac 
aws ec2 terminate-instances --instance-ids $ID
aws ec2 wait instance-terminated --instance-ids $ID
aws ec2 delete-security-group --group-id $SG
aws ec2 delete-key-pair --key-name vidore-gpu && rm ~/.ssh/vidore-gpu.pem

# anything left with this project's tag that isn't terminated?
aws ec2 describe-instances --filters Name=tag:project,Values=vidore-v3-loop \
      Name=instance-state-name,Values=pending,running,stopping,stopped --query 'Reservations[].Instances[].InstanceId'
aws ec2 describe-volumes --filters Name=tag:project,Values=vidore-v3-loop --query 'Volumes[].VolumeId'
