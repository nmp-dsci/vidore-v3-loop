Can EVIE learn from our gold pages? Yes, on the question side

You can fine-tune EVIE on each train question's gold pages. The cheap way trains only how EVIE reads questions and leaves the 2,942 stored page vectors alone, so it needs no 11-hour re-index and runs on this Mac. The catch is the data: there are 155 questions, and 115 of the 154 test questions share a gold page with them. So a gain on test could just mean the model memorised those pages, unless training leaves those pages out.

1 · the short answer

Possible, cheap and local, but the test can be fooled

yes

It can be done

Each train question comes with graded gold pages: those are the targets. The loss raises the gold pages' MaxSim scores and lowers every other page's. Sentence-transformers 6.1, already in our lock, ships a multi-vector trainer, and a plain PyTorch loop works too.

cheap

Train the question side only

EVIE uses one network for pages and questions. We keep the pages as they were indexed and let only a question copy learn. Each step then costs 0.61 s, and scoring a tuned model is the same 0.09 s search as today.

the catch

Train and test share pages

115 of the 154 test questions have a gold page that some train question also has. A model taught to lift those pages would gain on test without retrieving any better. The clean fix is to train without any test gold page, which leaves 304 of the 702 pairs.

What that means

  • An epoch over 155 questions takes ≈ 1.6 min. A 6-fold check of one setting at 5 epochs takes ≈ 40 min (est. from the step).
  • Adam's state for 446M parameters adds ≈ 3.6 GB (est.), which still fits.
  • Pages learning too means ≥ 2.3 h an epoch for the 702 positives alone, plus an 11.2 h re-index before every score. That route is for a rented GPU or nowhere.
  • The tuned part is ≈ 0.9 GB in bf16. It goes in data/cache/, which is never committed.

Why not re-embed the pages instead?

Re-embedding with the same model changes nothing, because the vectors come out identical. It only helps after the page side has been trained, which is route F3. So the real choice is between these two:

My view: the page side has the higher ceiling, but it isn't the best first step with 304 clean pairs. Start with the question side: about 40 minutes per check on the Mac and $0, which tests whether these labels carry signal. If it clears the gate, the page side (F3, with F2's synthetic questions, on a rented GPU) is the next ask. A null result on the question side won't rule the page side out, but it would make that spend harder to justify.

Three guards that keep the number honest

Train without any test gold pageDrop the 218 shared pages as positives and as negatives, so the model never gets a gradient from a test gold page. That leaves 304 of 702 pairs (80 full) from 105 of 155 questions; 50 train questions have only shared gold pages and drop out.test then stays clean on all 154 questions
Cross-validate by report, not by questionSix folds, one annual report each, built from the 141 single-report train questions: Bank of America 46, Citigroup 39, JPMorgan 18, Morgan Stanley 16, Goldman Sachs 15, Wells Fargo 7. A fold trains on the other five reports' questions and never sees the held-out report's pages, not even as negatives.measures better retrieval, not page memory

My expectation, not a measurement: a small gain at best, about 0 to +3 points on report folds. Tencent already trained EVIE on far more data than 105–155 questions, and a question-side change can only re-weight what a question looks for. It can't put information into a page vector that isn't there. The gate exists because tuning on this little data can just as easily make EVIE worse.
